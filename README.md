# dsh-explainer-video

A **vector explainer video** plugin for DeepSeek Harness (DSH).

Given a prompt plus source materials (PDF / PPTX / DOCX / text / video / image), it:

1. parses materials into notes, locators, and image assets;
2. optionally supplements them with web research (materials first, web second);
3. uses the **current session main model** to produce a constrained `storyboard.json`;
4. synthesizes narration through a configurable OpenAI-compatible `/v1/audio/speech` endpoint, picking one of the **nine Qwen3-TTS CustomVoice preset roles**;
5. renders deterministic vector frames as SVG (charts, icons, timelines, images);
6. muxes an H.264 + AAC MP4 with ffmpeg.

It is **not** a text-to-video model. Layout, icons, charts, and motion are generated by a built-in deterministic renderer, so results are reproducible, editable, and re-renderable.

---

## Install

```bash
pnpm add github:fred-chen/dsh-explainer-video#v0.1.0
```

or install it from the DSH plugin marketplace.

The package registers through `cordis.patch.yml`:

- settings page: `Plugins → dsh-explainer-video`
- tools: `explainer_video_generate`, `explainer_video_render`
- settings bridge: `/api/dsh-explainer-video/{config,save,test}`
- video/preview stream: `/api/dsh-explainer-video/artifacts/<token>`

> `sharp` is the only runtime npm dependency. `ffmpeg`/`ffprobe` must be available locally. PDF/Office parsing also needs `python3` with PyMuPDF / python-pptx / python-docx (a stdlib zip+XML fallback is attempted when missing).

## Quick start

```text
Generate a 3-minute Chinese vector explainer about why GPU rental prices did not
collapse after China's AI bubble burst, for a general tech audience, in a dark
neon infographic style. Use the PDF and PPT I provided.
```

Tool call example:

```json
{
  "prompt": "Generate a 3-minute Chinese explainer: why didn't GPU rents crash? General tech audience.",
  "materials": [
    "/path/to/report.pdf",
    "/path/to/deck.pptx"
  ],
  "durationSec": 180,
  "style": "dark-neon",
  "voice": "uncle_fu",
  "webMode": "auto"
}
```

Storyboard + preview only:

```json
{
  "prompt": "Same as above",
  "materials": ["/path/to/report.pdf"],
  "planOnly": true
}
```

Re-render after editing `storyboard.json` (no script regeneration, no new TTS if cached):

```json
{
  "storyboardPath": ".dsh-explainer-video/job-.../storyboard.json",
  "voice": "dylan"
}
```

## LLM routing

Default:

- `llmProvider` and `llmModel` **empty** → use the current Agent session's main model (`exec.agent.options.provider/model`).
- The settings page can override provider/model, for example to use a cheaper model for script writing.

Generation is split into two calls:

1. `extractEvidence`: condense material notes into fact cards with `sourceId` values; no invented citations.
2. `generateStoryboard`: emit strict JSON scenes with `narration`, `ttsText`, `elements`, and `sourceIds`.

`storyboard.json` is validated for layouts, icon names, chart values, image `assetId`s, reference IDs, duration/fps, and more. On failure the raw response is retained for debugging.

## TTS: configurable endpoint + preset voices

Defaults match `dsh-tts`:

| Item | Default |
|---|---|
| Endpoint | `http://ai4090:8080/v1/audio` |
| Model | `Qwen3-TTS-12Hz-1.7B-CustomVoice` |
| Voice | `uncle_fu` |
| Format | `wav` |
| Sample rate | 0 (server native) |

Accepted endpoint forms are normalized to `/v1/audio`:

- `http://host:8080`
- `http://host:8080/v1`
- `http://host:8080/v1/audio`
- `http://host:8080/v1/audio/speech`

CustomVoice preset roles:

| id | Description |
|---|---|
| `uncle_fu` | deep, mature male (Chinese) |
| `dylan` | bright Beijing young male (Chinese, Beijing) |
| `eric` | husky, bright Chengdu male (Chinese, Sichuan) |
| `vivian` | bright, slightly sharp young female (Chinese) |
| `serena` | warm, soft young female (Chinese) |
| `ryan` | rhythmic dynamic male (English) |
| `aiden` | sunny American male (English) |
| `ono_anna` | light, playful female (Japanese) |
| `sohee` | warm, emotive female (Korean) |

At runtime the plugin reads `/v1/audio/voices?model=...` and validates against the actual server list. Passing an unsupported name such as `Cherry` returns an explicit error with the available values instead of silently failing.

With `Qwen3-TTS-12Hz-1.7B-VoiceDesign`, `voice` accepts a free-form description such as “a low, husky middle-aged male voice, slow pace”.

Narration controls:

- `ttsLanguage`: empty = auto; `Chinese` / `English` / `Japanese` / `Korean` also accepted.
- `ttsInstructions`: emotion, pace, style, e.g. “calm, clear, documentary narration, moderate pace”.
- `ttsApiKey`: secret field; stored in settings, never returned in plaintext.
- `ttsFormat`, `ttsSampleRate`, `ttsTimeoutSec`, `ttsExtraParams` are configurable.

Each scene is synthesized separately and aligned to scene boundaries. The audio cache key includes endpoint, model, voice, language, instructions, format, sample rate, extra params, and input text, so changed settings never reuse stale audio.

## Web supplementation

`webMode`:

- `auto` (default): usually skip when materials suffice; search when supplementation/comparison is needed;
- `off`: materials only;
- `always`: force research.

Flow:

1. the LLM reads material fact cards and proposes up to 6 queries and reasons;
2. the plugin calls the host `ctx.web` search and fetch;
3. pages are cleaned into notes with URL, title, and date;
4. web notes are passed as secondary evidence, and `sourceIds` must reference existing IDs;
5. `web-research.json` is written; frame corners show `source: src1, web2`, and end references list full URLs.

**Citations primarily come from materials**; web content supplements and cross-checks, but this is not a line-by-line fact audit. If the host has no web provider, the plugin warns and continues with materials.

## Storyboard and rendering

`storyboard.json` is semantic, not per-frame SVG:

```json
{
  "version": 1,
  "title": "Why GPU rents did not crash",
  "language": "zh",
  "style": "dark-neon",
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "references": [{ "id": "src1", "kind": "file", "label": "report.pdf p.3" }],
  "chapters": [{ "id": "ch1", "title": "Conclusion first" }],
  "scenes": [
    {
      "id": "s01",
      "chapterId": "ch1",
      "layout": "hero",
      "kicker": "STAR 50",
      "headline": "China's AI bubble just burst",
      "subhead": "A valuation reset, not a demand collapse",
      "narration": "Let's state the conclusion first...",
      "ttsText": "Let's state the conclusion first...",
      "sourceIds": ["src1"],
      "transition": "fade",
      "elements": [
        { "type": "icon", "name": "chart-down", "size": 180, "color": "#ff5c6c" },
        { "type": "pill", "text": "STAR 50 ↓ 45%", "color": "#ff5c6c" }
      ]
    }
  ]
}
```

Layouts: `hero`, `split`, `chart`, `diagram`, `timeline`, `comparison`, `quote`.

Elements: `icon` (23 built-in), `pill`, `text`, `chart` (bar/line/area), `diagram` (nodes/edges), `timeline`, `image`, `arrow`.

Pipeline:

```text
storyboard.json
  → layout / style / chapter progress
  → per-frame SVG
  → sharp rasterization to RGBA
  → ffmpeg rawvideo pipe
  → H.264 (CRF 18) + AAC (192k) + faststart
  → ffprobe verification
```

Style presets:

- `dark-neon`: near-black background, neon accents, bold type, grid;
- `tech-blue`: cool tech-blue charts;
- `paper-editorial`: high-contrast editorial paper.

Subtitles:

- `none`: no burned captions;
- `burn`: captions rendered inside SVG (ffmpeg lacks libass/subtitles here);
- `srt`: write a sidecar SRT.

## Outputs

A run leaves:

```text
.dsh-explainer-video/job-.../
  materials.json
  web-research.json
  storyboard.json
  script.md
  narration.wav
  scene-01.wav ...
  subtitles.srt (when subtitleMode=srt)
  <title>.mp4
  preview/ (when planOnly)
```

The tool returns:

- `filePath`, `videoUrl`
- `storyboardPath`, `scriptPath`, `materialsPath`, `webResearchPath`
- `previewUrls`
- `durationSec`, `sceneCount`, `width/height/fps`
- `style`, `voice`, `ttsModel`, `ttsLanguage`, `ttsInstructions`
- `webMode`, `webQueries`, `webSources`
- `warnings`

`videoUrl` uses the actual host port:

```text
http://127.0.0.1:<webServer.port>/api/dsh-explainer-video/artifacts/<token>
```

## Settings page

`Plugins → dsh-explainer-video` includes:

- LLM provider/model (empty = current main model), max tokens, default language;
- TTS endpoint, model, voice, language, instructions, format, sample rate, timeout, API key;
- web mode and budgets;
- style, resolution, fps, target duration, subtitle mode, output directory, BGM, total timeout;
- a “Test TTS / media tools” button that reads `/v1/models` and `/v1/audio/voices`, checks ffmpeg/ffprobe/sharp, and shows LLM/web service availability.

## Requirements and limitations

- Node.js >= 20;
- `ffmpeg` / `ffprobe` (H.264/AAC);
- `sharp` (installed with the package);
- `python3` + PyMuPDF / python-pptx / python-docx for PDF/Office parsing (fallbacks exist but are lower fidelity);
- ASR is optional: without whisper, video materials are metadata/style references only; configure `asrEndpoint` to transcribe;
- visuals are deterministic vector rendering, not generative video; complex 3D, real people, and live-action shots are out of scope;
- `burn` subtitles are drawn in SVG because ffmpeg lacks libass here;
- web citations require host `ctx.web`; otherwise the plugin degrades gracefully.
